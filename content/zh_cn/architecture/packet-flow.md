# 数据包和事件流

本页解释概念流程，而不是列出每种数据包类型。当设置只部分工作时，它非常有用：例如，客户端已连接但没有距离感音频播放，或者插件已连接但绑定从未完成。

VoiceCraft 有两个相关平面：

- 语音平面：
  玩家客户端通过`VoiceCraft.Server`发送和接收实时语音数据
- Minecraft 状态平面：
  Bedrock 插件或 Java 端插件通过 `McHttp`、`McWss` 或 `McTcp` 发送实体、位置、世界、绑定和效果更新

两个平面都必须正常，距离感语音才会按预期工作。

## 高层流程

1. `VoiceCraft.Server` 启动并加载 `ServerProperties.json`。
2. 玩家打开 `VoiceCraft.Client` 并连接到服务器 UDP 端点。
3. Minecraft 传输客户端使用其配置的令牌进行身份验证。
4. Minecraft 端创建、发现或更新实体。
5. 位置、世界 ID、可见性、静音/Deafen 和效果更新流入服务器世界模型。
6. 服务器发送连接的客户端所需的状态。
7. 客户端在本地播放生成的语音行为。

顺序可能因拓扑而略有不同。重点是客户端登录和 Minecraft 传输登录是两个独立事件：一侧可以正常工作，另一侧仍然失败。

## 典型事件类别

- 登录/注销
- ping / 信息
- 实体创建/销毁
- 元数据更新
- 审核更新
- 效果更新
- 音频传输事件

## 绑定流程

绑定流程将 Minecraft 玩家或实体链接到 VoiceCraft 端客户端身份。

典型 Bedrock 流程：

1. 该插件连接到 `McHttp` 或 `McWss`。
2. 玩家运行或接收游戏内绑定命令。
3. 该插件将绑定相关数据发送到 VoiceCraft。
4. VoiceCraft 将语音客户端与游戏内实体关联起来。
5. 位置和世界更新开始影响客户端听到的内容。

典型的 Java/Geyser 流程：

1. `VoiceCraft.Java` 连接到 `McTcp`。
2. 该插件跟踪 Java 端玩家的生命周期和位置。
3. 玩家使用配置的语音绑定命令。
4. `VoiceCraft.Java` 将绑定/更新数据发送到 VoiceCraft。

如果绑定失败，首先检查令牌匹配和传输可达性，然后检查玩家是否有活动的 VoiceCraft 客户端会话。

## 逐层调试

| 症状 | 首先要检查的层 | 典型原因 |
|---------|----------------------|---------------|
| 客户端无法连接 | 语音平面 | 服务器主机错误、UDP 端口关闭、服务器未运行 |
| 插件/插件无法连接 | Minecraft 状态平面 | 错误的传输令牌、错误的主机绑定、阻塞的 TCP/HTTP/WebSocket 路径 |
| 客户端已连接但听不到距离感音频 | 实体/位置状态 | 绑定缺失，`PositioningType` 不匹配，无位置更新 |
| 音频存在，但范围/效果感觉不对 | 效果/状态同步 | 错误的效果位掩码、陈旧的实体元数据、不匹配的客户端设置 |

## 为什么这很重要

调试时，有助于了解您的问题是否是：

- 认证
- 传输可达性
- 实体创建
- 绑定关联
- 元数据和位置同步
- 音频采集/播放

大多数真正的失败都是因为其中一层损坏而其他层看起来仍然正常而发生的。
