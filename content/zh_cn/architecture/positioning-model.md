# 定位模型

VoiceCraft 支持服务器端和客户端定位模型。

定位决定了由谁提供邻近音频所依赖的位置数据。如果选择了错误的模式，客户端可以成功连接，但仍然会听到错误的人、没有人听到或忽略距离变化。

## `PositioningType`

- `0 = Server`
- `1 = Client`

该值必须在服务器和客户端之间保持一致。

将服务器值设置为：

```text
VoiceCraftConfig.PositioningType
```

在客户端网络设置或 `Settings.json` 中设置客户端值。

## 服务器端定位

最佳时间：

- 服务器或集成层可以提供权威的世界状态
- 你想要更集中的行为
- 您使用 `McHttp` 运行 BDS
- 你用 `GeyserVoice` 运行 Java/Geyser
- 您希望工作人员/审核工具能够推断服务器拥有的实体状态

在此模型中，Minecraft 端集成将位置和世界更新发送到 `VoiceCraft.Server`。客户端接收足够的状态以在本地呈现邻近音频。

将此用作生产部署的默认值。

## 客户端定位

最佳时间：

- 环境受到限制
- 服务器端世界整合有限
- 一些托管限制阻碍了正常的集成路径

在此模型中，客户端需要提供或导出更多自己的定位上下文。它对于受限或实验环境很有用，但更容易错误配置，因为每个客户端都必须同意服务器设置。

仅当您知道为什么服务器端定位对于目标设置不实用时才使用此选项。

## 选择模式

| 设置 | 推荐模式 | 原因 |
|-------|------------------|--------|
| 基岩专用服务器 + `McHttp` | `0 = Server` | BDS插件可以报告权威的世界状态 |
| 当地基岩世界 + `McWss` | 通常 `0 = Server` | 插件仍然可以通过隧道发送状态 |
| Java + Geyser/Floodgate + `GeyserVoice` | `0 = Server` | 插件跟踪玩家生命周期和位置 |
| 实验性仅限本地设置 | 视情况而定 | 仅当集成无法提供状态时才使用客户端 |

## 为什么不匹配会破坏音频预期

如果客户端和服务器在定位模式上不一致，您可能会看到以下症状：

- 语音客户端已连接但听不到预期的接近度
- 实体出现但行为异常
- 整合看起来部分健康，但位置逻辑是错误的

## 验证步骤

1. 检查 `ServerProperties.json` 中的 `VoiceCraftConfig.PositioningType`。
2. 检查客户端网络设置。
3. 更改本地值后重新启动客户端。
4. 重新连接 Minecraft 传输。
5. 在游戏中移动玩家并确认服务器/客户端行为随距离而变化。

如果设置仍然失败，请接下来调试绑定流。如果语音会话未绑定到游戏内实体，则正确的定位模式无济于事。
