# 故障排除矩陣

當您需要基於症狀的診斷而不是通用檢查表時，請使用此頁面。

## 症狀：客戶端已連接，但沒有人聽到任何聲音

檢查：

1. `PositioningType` 匹配
2. 綁定流程完成
3. 實體接收世界和位置更新
4. 客戶沒有本地靜音或耳聾
5. 伺服器沒有使該實體靜音或震耳欲聾

如何驗證：

- 執行 `list --clientsOnly` 以確認語音用戶端存在
- 執行`list`並檢查相關實體是否有變化的位置
- 使用客戶端麥克風測試和輸出測試來排除本地音訊設備

## 症狀：插件已連接，但綁定無法正常工作

檢查：

1. 令牌是正確的
2. 預期的實體已創建
3. 玩家使用了正確的綁定金鑰
4. 綁定腳本事件正在觸發

常見原因：

- 玩家複製了過期或重新產生的綁定金鑰
- 插件包版本與伺服器/客戶端版本不匹配
- 自訂插件邏輯攔截或繞過庫存綁定流程

## 症狀：GeyserVoice 已安裝，但 Java 端橋永遠無法使用

檢查：

1. VoiceCraft 上啟用了 `McTcp`
2. `config.voicecraft.transport.host`、`config.voicecraft.transport.port` 和 `config.voicecraft.transport.login-token` 匹配
3. 直接與代理模式是有意配置的
4. 如果啟用 `auto-start`，則運行時在逾時內準備就緒

也要檢查插件是否安裝在正確的層上：直接Paper模式需要Paper/Folia，而代理模式需要代理和後端節點。

## 症狀：Direct Paper模式在手動重新連接後有效，但在啟動時無效

檢查：

1. `config.voicecraft.auto-start`
2. `install-directory`
3. `ready-timeout-ms`
4. 運行時進程的啟動所有權

如果外掛程式在託管運行時準備就緒之前啟動，請增加逾時或使用具有自己的重新啟動策略的外部 VoiceCraft 服務。

## 症狀：代理模式在一個後端可以工作，但在伺服器切換時中斷

檢查：

1. 代理是真相的來源
2. 後端節點不會嘗試擁有 VoiceCraft 連接
3. 快照轉送在交換器之間保持完整
4. 世界 ID 命名空間邏輯保持一致

如果只有一個後端失敗，請將其 GeyserVoice 配置和插件版本與正常運作的後端進行比較。

## 症狀：`McWss` 不穩定

檢查：

1. `CommandsPerTick`
2. `MaxByteLengthPerCommand`
3. 實體流失和資料包突發大小
4. `McHttp` 是否更合適

如果世界正在成為一個長期運作的共享伺服器，請將不穩定視為轉向 BDS + `McHttp` 的標誌。

## 症狀：VoiceCraft 伺服器啟動，但傳輸使用者無法連接

檢查：

1. 主機綁定
2. 暴露端口
3. 防火牆
4. 選擇了錯誤的運送類型
5. 運行時覆蓋更改預期值

快速分割：

- 客戶端連線問題通常是 UDP 端點或客戶端設定
- 插件/插件連接問題通常是 `McHttp`、`McWss` 或 `McTcp`
- 綁定/鄰近問題通常發生在兩個連線都已存在之後
