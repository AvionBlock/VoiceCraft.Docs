# 資料包和事件流

本頁解釋概念流程，而不是列出每種資料包類型。當設定部分工作時，它非常有用：例如，客戶端已連接但沒有鄰近音訊播放，或插件已連接但綁定從未完成。

VoiceCraft 有兩個相關平面：

- 語音平面：
  玩家客戶端透過`VoiceCraft.Server`發送和接收即時語音數據
- Minecraft 狀態平面：
  Bedrock 外掛程式或 Java 端外掛程式透過 `McHttp`、`McWss` 或 `McTcp` 發送實體、位置、世界、綁定和效果更新

兩個平面都必須正常，proximity voice 才會按預期工作。

## 高層流程

1. `VoiceCraft.Server` 啟動並載入 `ServerProperties.json`。
2. 玩家開啟 `VoiceCraft.Client` 並連接到伺服器 UDP 端點。
3. Minecraft 傳輸用戶端使用其配置的令牌進行身份驗證。
4. Minecraft 端建立、發現或更新實體。
5. 位置、世界 ID、可見性、靜音/Deafen 和效果更新流入伺服器世界模型。
6. 伺服器發送連線的客戶端所需的狀態。
7. 客戶端在本地呈現產生的語音行為。

順序可能因拓撲而略有不同。重點是用戶端登入和 Minecraft 傳輸登入是兩個獨立事件：一側可以正常工作，另一側仍然失敗。

## 典型事件類別

- 登入/登出
- ping / 訊息
- 實體創建/銷毀
- 元資料更新
- 審核更新
- 效果更新
- 音訊傳輸事件

## 綁定流程

綁定流程將 Minecraft 玩家或實體連結到 VoiceCraft 端用戶端身分。

典型 Bedrock 流程：

1. 此插件連接到 `McHttp` 或 `McWss`。
2. 玩家運行或接收遊戲內綁定命令。
3. 該插件將綁定相關資料傳送到 VoiceCraft。
4. VoiceCraft 將語音用戶端與遊戲內實體關聯起來。
5. 位置和世界更新開始影響用戶端聽到的內容。

典型的 Java/Geyser 流程：

1. `GeyserVoice` 連接到 `McTcp`。
2. 此外掛程式追蹤 Java 端玩家的生命週期和位置。
3. 玩家使用配置的語音綁定命令。
4. `GeyserVoice` 將綁定/更新資料傳送至 VoiceCraft。

如果綁定失敗，請先檢查令牌匹配和傳輸可達性，然後檢查玩家是否有活動的 VoiceCraft 用戶端會話。

## 逐層調試

| 症狀 | 首先要檢查的層 | 典型原因 |
|---------|----------------------|---------------|
| 客戶端無法連接 | 語音平面 | 伺服器主機錯誤、UDP 連接埠關閉、伺服器未執行 |
| 插件/插件無法連接 | Minecraft 狀態平面 | 錯誤的傳輸令牌、錯誤的主機綁定、阻塞的 TCP/HTTP/WebSocket 路徑 |
| 用戶端已連線但聽不到 proximity audio | 實體/位置狀態 | 綁定缺失，`PositioningType` 不匹配，無位置更新 |
| 音頻存在，但範圍/效果感覺不對 | 效果/狀態同步 | 錯誤的效果位元遮罩、陳舊的實體元資料、不匹配的客戶端設置 |

## 為什麼這很重要

調試時，有助於了解您的問題是否為：

- 認證
- 傳輸可達性
- 實體創建
- 綁定關聯
- 元資料和位置同步
- 音訊擷取/播放

大多數真正的失敗都是因為其中一層損壞而其他層看起來仍然正常而發生的。
