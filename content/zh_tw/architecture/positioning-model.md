# 定位模型

VoiceCraft 支援伺服器端和用戶端定位模型。

定位決定了由誰提供距離感音訊所依賴的位置資料。如果選擇了錯誤的模式，客戶端可以成功連接，但仍然會聽到錯誤的人、聽不到任何人，或忽略距離變化。

## `PositioningType`

- `0 = Server`
- `1 = Client`

該值必須在伺服器和客戶端之間保持一致。

將伺服器值設為：

```text
VoiceCraftConfig.PositioningType
```

在客戶端網路設定或 `Settings.json` 中設定客戶端值。

## 伺服器端定位

最佳時間：

- 伺服器或整合層可以提供權威的世界狀態
- 你想要更集中的行為
- 您使用 `McHttp` 執行 BDS
- 你用 `VoiceCraft.Java` 運行 Java/Geyser
- 您希望工作人員/審核工具能夠推斷伺服器擁有的實體狀態

在此模型中，Minecraft 端整合將位置和世界更新傳送至 `VoiceCraft.Server`。用戶端接收足夠的狀態，以便在本地播放距離感音訊。

將此用作生產部署的預設值。

## 客戶端定位

最佳時間：

- 環境受到限制
- 伺服器端世界整合有限
- 一些託管限制阻礙了正常的整合路徑

在此模型中，客戶端需要提供或匯出更多自己的定位上下文。它對於受限或實驗環境很有用，但更容易錯誤配置，因為每個客戶端都必須同意伺服器設定。

僅當您知道為什麼伺服器端定位對於目標設定不實用時才使用此選項。

## 選擇模式

| 設定 | 推薦模式 | 原因 |
|-------|------------------|--------|
| Bedrock 專用伺服器 + `McHttp` | `0 = Server` | BDS插件可以報告權威的世界狀態 |
| 本地 Bedrock 世界 + `McWss` | 通常 `0 = Server` | 插件仍然可以透過隧道發送狀態 |
| Java + Geyser/Floodgate + `VoiceCraft.Java` | `0 = Server` | 插件追蹤玩家生命週期和位置 |
| 實驗性僅限本地設置 | 視情況而定 | 僅當整合無法提供狀態時才使用客戶端 |

## 為什麼不匹配會破壞音訊預期

如果客戶端和伺服器在定位模式上不一致，您可能會看到以下症狀：

- 語音用戶端已連線但聽不到預期的距離感效果
- 實體出現但行為異常
- 整合看起來部分健康，但位置邏輯是錯誤的

## 驗證步驟

1. 檢查 `ServerProperties.json` 中的 `VoiceCraftConfig.PositioningType`。
2. 檢查客戶端網路設定。
3. 更改本地值後重新啟動客戶端。
4. 重新連接 Minecraft 傳輸。
5. 在遊戲中移動玩家並確認伺服器/客戶端行為隨距離而變化。

如果設定仍然失敗，請接下來偵錯綁定流程。如果語音會話未綁定到遊戲內實體，則正確的定位模式無濟於事。
