# Усиление безопасности

Эта страница посвящена снижению операционных рисков в реальных развертываниях.

Безопасность VoiceCraft в основном заключается в ограничении доступа к endpoints транспорта, защите общих токенов и сохранении оперативного контроля только со стороны персонала от обычных игроков.

## 1. Поверните каждый сгенерированный токен.

Никогда не сохраняйте сгенерированные значения по умолчанию для:

- `McHttpConfig.LoginToken`
- `McWssConfig.LoginToken`
- `McTcpConfig.LoginToken`

Относитесь к ним как к общим секретам.

Используйте токен только с соответствующей интеграцией:

- `McHttpConfig.LoginToken` для BDS `McHttp`
- `McWssConfig.LoginToken` для локальной основы `McWss`
- `McTcpConfig.LoginToken` для моста GeyserVoice/Java

## 2. Выставляйте только нужные транспорты

Не публикуйте каждый транспорт только потому, что он существует.

Примеры:

- Хост только для Bedrock:
  обычно только `McHttp`
- Хост моста Java:
  обычно только `McTcp`
- локальный тестовый хост:
  часто только петля `McWss`

## 3. Используйте петлю, когда это возможно

Предпочитаю:

- `127.0.0.1`
- `localhost`

когда клиент находится на той же машине.

Используйте `0.0.0.0` только тогда, когда действительно требуется удаленный доступ.

## 4. Жесткая политика брандмауэра

Разрешите только то, что вам нужно:

- UDP-порт VoiceCraft
- конкретный транспортный порт HTTP или TCP
- дополнительный порт WebSocket

Не открывайте широко транспортные порты, если интегрирующий узел известен и фиксирован.

Помните, что UDP endpoint клиента и endpoints транспорта Minecraft обслуживают разных пользователей. Игрокам нужен голосовой UDP endpoint. Аддону/плагину требуется выбранный endpoint транспорта Minecraft.

## 5. Отдельная среда

Используйте разные:

- жетоны
- файлы конфигурации
- каталоги
- порты

для производства, постановки и локального тестирования.

## 6. Будьте осторожны с средами выполнения, управляемыми плагинами.

Если `GeyserVoice` управляет средой выполнения VoiceCraft:

- держать каталог установки под контролем
- понять, кому принадлежит поведение при перезапуске
- подтвердить, что журналы собираются в предсказуемом месте
- убедитесь, что сгенерированные файлы времени выполнения не доступны для записи ненадежным пользователям
- узнайте, ожидается ли `shutdown-on-disable` в процессе перезапуска

## 7. Избегайте случайного использования `DisabledPacketTypes`.

Это не обычная функция закалки.

Это прежде всего для:

- отладка
- временное смягчение
- экспериментирование по протоколу

Слепое отключение типов пакетов может привести к нарушению аутентификации, синхронизации или звука.

## 8. Ограничить оперативные команды

Для `GeyserVoice` оставьте эти данные только для персонала:

- `/voice connect`
- `/voice reconnect`
- `/voice disconnect`
- `/voice reload`

Для консоли сервера VoiceCraft ограничьте доступ только доверенным операторам. Такие команды, как `kick`, `mute`, `deafen`, а также редактирование метаданных могут влиять на живых игроков.

## 9. Защитите содержимое резервной копии

Резервные копии могут содержать:

- жетоны транспорта
- топология хоста и порта
- детали схемы обслуживания

Относитесь к резервным копиям конфигурации как к конфиденциальным операционным данным.

## 10. Обзор артефактов общественной поддержки

Прежде чем публиковать скриншоты, журналы или конфигурации публично, удалите:

- транспортировать токены входа
- публичные IP-адреса, если они не должны разглашаться
- секреты сервисной оболочки
- сгенерированные ключи привязки, если они все еще активны
- идентификаторы игроков, если конфиденциальность имеет значение

## Контрольный список закалки

- сгенерированные токены заменены
- включены только необходимые транспорты
- loopback-адрес, используемый для клиентов на том же хосте
- правила брандмауэра, где это возможно, ограничиваются известными источниками
- Операционные команды GeyserVoice ограничены
- резервные копии надежно хранятся
- Версии релиза и аддонов/плагинов сохраняются согласованными
