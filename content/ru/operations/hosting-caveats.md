# Предостережения относительно хостинга

Различные поставщики и стили развертывания влияют на то, какая топология VoiceCraft является реалистичной.

Прежде чем выбирать топологию, подтвердите два сетевых пути:

1. игроки могут достичь UDP-эндпоинта VoiceCraft
2. среда выполнения на стороне Minecraft может достичь выбранного эндпоинта транспорта

Многие проблемы с хостингом возникают из-за блокировки одного из этих путей, в то время как другой все еще работает.

## Bedrock-хосты

`McHttp` обычно является лучшим транспортом Bedrock, но только если узел BDS может достичь эндпоинта VoiceCraft.

Распространенные блокаторы:

- ограничения исходящего HTTP
- отсутствуют разрешения модуля
- миры, где поддержка скриптов ограничена

Если провайдер блокирует исходящий HTTP или необходимые скриптовые модули, `McHttp` может быть технически корректным, но недоступным в рабочем режиме.

## Поставщики виртуального хостинга

Некоторые провайдеры не разрешают:

- кастомные слушатели
- исходящий HTTP с игрового сервера
- дополнительные вспомогательные процессы

В таких средах технически поддерживаемая топология может быть заблокирована в рабочем режиме.

Спросите у провайдера об исходящем HTTP/TCP от игрового сервера и вспомогательных процессах. Общего ответа «Разрешены плагины» недостаточно.

## Ограничения, похожие на Aternos

На хостинге с жесткими ограничениями связь в стиле HTTP может быть заблокирована или непрактична.

Когда это произойдет:

- Bedrock BDS + `McHttp` может оказаться нежизнеспособным
- альтернативы локального мира или на стороне клиента могут быть единственным путем

Не предполагайте, что бесплатный/ограниченный хост может использовать ту же топологию, что и VPS или выделенный компьютер.

## Предостережения по докеру и контейнерам

Контейнеры помогают с изоляцией, но вам все равно нужно:

- публикация портов
- стабильное монтирование томов для конфигурации
- правильная межконтейнерная сеть
- явная публикация UDP-эндпоинта клиента VoiceCraft
- постоянное хранилище для управляемых каталогов среды выполнения

## Обратные прокси

Не все транспорты VoiceCraft имеют форму обратного прокси:

- `McHttp` более естественно подходит для инструментов HTTP.
- `McTcp` — это необработанный TCP
- `McWss` ведет себя иначе, чем обычный HTTP.

Не рассчитывайте, что одна ingress-стратегия подойдет для всех этих транспортов.

Инструменты HTTP могут помочь с `McHttp`, но они не решают автоматически необработанный `McTcp` или клиентский UDP-трафик.

## Предостережения по сети Java

Для развертываний прокси-сервера `VoiceCraft.Java`:

- прокси должен надежно достигать VoiceCraft
- Внутренние узлы Paper должны надежно достигать пути сообщения прокси-сервера.
- модель собственности должна оставаться ясной

Если прокси-сервер не может полностью владеть мостом, топология становится хрупкой.

## Практический контрольный список поставщиков

Спросите или проверьте:

- Могут ли игроки подключиться к кастомному UDP-порту?
- Может ли игровой сервер отправлять исходящие HTTP-запросы?
- Может ли игровой сервер открывать или подключаться к необработанным TCP-портам?
- Могу ли я запустить дополнительный процесс для `VoiceCraft.Server`?
- Могу ли я сохранить `config/ServerProperties.json`?
- Могу ли я установить или обновить пакеты поведения/ресурсов Bedrock?
- В сетях Java могут ли сообщения плагинов надежно передаваться между сервером и прокси-сервером?

Если какой-либо ответ отрицательный, выберите топологию, которая позволяет избежать этого требования, или переместите VoiceCraft в инфраструктуру, которую вы контролируете.
