# Переопределения времени выполнения

Сервер VoiceCraft поддерживает переопределения во время выполнения с помощью корневых параметров CLI.

Переопределения во время выполнения изменяют запущенный процесс без постоянной перезаписи `config/ServerProperties.json`. Они полезны, когда панель, контейнер, systemd-юнит или плагин запускают сервер и должны передать значения, специфичные для среды.

Эти параметры подходят, когда:

- вам нужны значения, специфичные для среды, без редактирования JSON
- менеджер процессов вводит значения при запуске
- `VoiceCraft.Java` автоматически запускает среду выполнения VoiceCraft.
- вы тестируете несколько транспортных топологий из одной и той же папки установки

Если вы выполняете простую установку вручную, сначала отредактируйте `ServerProperties.json` и используйте переопределения только тогда, когда они сделают развертывание более понятным.

## Поддерживаемые параметры

- `--exit-on-invalid-properties` / `-eip`
- `--language <culture>` / `-l`
- `--transport-mode <mode>` / `-tm`
- `--transport-host <host>` / `-th`
- `--transport-port <port>` / `-tp`
- `--server-key <token>` / `-sk`

## Приоритет переопределений

При запуске VoiceCraft загружает `ServerProperties.json`, а затем применяет переопределения времени выполнения для текущего процесса.

Это означает:

- файл JSON остается постоянным значением по умолчанию
- значение CLI выигрывает для этого запуска
- перезапуск без того же флага CLI возвращает значение JSON
- резервные копии по-прежнему должны включать конфигурацию JSON, даже если в вашем производственном процессе используются переопределения.

## Что меняет каждый вариант

### `--language`

Переопределяет `VoiceCraftConfig.Language` для текущего процесса.

Пример:

```bash
./VoiceCraft.Server --language ru-RU
```

Используйте это для журналов и диагностики. Это не меняет язык пользовательского интерфейса клиента.

### `--transport-mode`

Включает только выбранный транспорт Minecraft для текущего запуска.

Принятые значения:

- `http`
- `tcp`
- `wss`
- псевдонимы, такие как `ws`, `websocket`, `websockets`
- псевдонимы, такие как `local-socket`, `tcp-socket`, нормализуются до `tcp`

Примеры:

```bash
./VoiceCraft.Server --transport-mode http
./VoiceCraft.Server --transport-mode tcp
./VoiceCraft.Server --transport-mode http,tcp
```

Если установлено, VoiceCraft сначала отключает все транспорты Minecraft, а затем повторно включает только выбранные.

Это самый безопасный способ запустить одноцелевой процесс. Например, хост, поддерживающий только BDS, может начинаться с `--transport-mode http`, даже если конфигурация JSON все еще содержит значения по умолчанию для других транспортов.

### `--transport-host`

Переопределяет транспортный хост Minecraft:

- `McHttpConfig.Hostname`
- `McWssConfig.Hostname`
- `McTcpConfig.Hostname`

Пример:

```bash
./VoiceCraft.Server --transport-host 0.0.0.0
```

Для `McHttp` и `McWss` VoiceCraft применяет хост к имени хоста в стиле URI. Для `McTcp` применяется простое поле хоста.

### `--transport-port`

Переопределяет транспортный порт Minecraft:

- Порт URI в `McHttpConfig.Hostname`
- Порт URI в `McWssConfig.Hostname`
- `McTcpConfig.Port`

Пример:

```bash
./VoiceCraft.Server --transport-port 9055
```

Будьте осторожны, когда несколько транспортов используют один и тот же порт по умолчанию. Если вы включаете несколько транспортов с одним переопределением, убедитесь, что полученные привязки действительны для вашей платформы и топологии.

### `--server-key`

Переопределяет общий токен входа, используемый:

- `McHttpConfig.LoginToken`
- `McWssConfig.LoginToken`
- `McTcpConfig.LoginToken`

Пример:

```bash
./VoiceCraft.Server --server-key "prod-secret-token"
```

Используйте это, когда секреты предоставляются менеджером процессов или плагином. Не помещайте производственные токены непосредственно в файлы общедоступных служб, снимки экрана или общие журналы поддержки.

## Хорошие примеры развертывания

### Выделенный хост BDS

```bash
./VoiceCraft.Server --transport-mode http --transport-host 0.0.0.0 --transport-port 9050
```

### Хост моста Java

```bash
./VoiceCraft.Server --transport-mode tcp --transport-host 0.0.0.0 --transport-port 9050
```

### Локальное одиночное тестирование

```bash
./VoiceCraft.Server --transport-mode wss --transport-host 127.0.0.1 --transport-port 9051
```

## Пример systemd

```ini
[Service]
WorkingDirectory=/opt/voicecraft
ExecStart=/opt/voicecraft/VoiceCraft.Server --transport-mode http --transport-host 0.0.0.0 --transport-port 9050
Restart=always
```

Используйте файл среды или менеджер секретов для `--server-key`, если токен не должен находиться непосредственно в unit-файле.

## Пример контейнера

```bash
./VoiceCraft.Server --transport-mode tcp --transport-host 0.0.0.0 --transport-port 9050 --server-key "$VOICECRAFT_TOKEN"
```

Это обеспечивает возможность повторного использования образа, позволяя каждой среде предоставлять свой собственный токен и привязку.

## Важное поведение

- переопределения во время выполнения являются локальными для процесса
- они не переписывают навсегда `ServerProperties.json`
- они отлично подходят для тестирования и автоматизации
- они уменьшают необходимость в нескольких копиях конфигурации
- если менеджер процессов перезапускает сервер, он должен каждый раз передавать одни и те же переопределения
- если значение в журналах выглядит неправильно, проверьте конфигурацию JSON и аргументы запуска.

## Когда не следует использовать переопределения

Избегайте переопределений, когда:

- вы все еще изучаете форму конфигурации
- вы ожидаете, что другой администратор будет проверять только `ServerProperties.json`
- у вас нет надежного места для хранения секретов вне файла конфигурации
- переопределение делает неясным, какой транспорт на самом деле включен
