# Виды транспорта

VoiceCraft имеет несколько транспортных слоев, ориентированных на Minecraft. Выбор правильного варианта важен для обеспечения стабильности и простоты развертывания.

Транспорт — это путь, по которому автоматизация Minecraft отправляет состояние в `VoiceCraft.Server`. Он отделен от голосового UDP endpoint, который используют клиенты игроков.

Используйте эту страницу перед редактированием `McHttpConfig`, `McWssConfig` или `McTcpConfig`.

## Быстрое сравнение

| Транспорт | Типичный клиент | Форма endpoint | Лучше всего подходит для | Поле токена |
|-----------|------------------|----------------|----------|-------------|
| `McHttp` | `VoiceCraft.Addon.Core.McHttp` | HTTP endpoint | Выделенный сервер Bedrock | `McHttpConfig.LoginToken` |
| `McWss` | `VoiceCraft.Addon.Core.McWss` | WebSocket + командный туннель | локальные миры Bedrock и тестирование | `McWssConfig.LoginToken` |
| `McTcp` | `GeyserVoice` | необработанный TCP-мост | Сценарии Java, Geyser, proxy или Paper Bridge | `McTcpConfig.LoginToken` |

Не выбирайте транспорт только по номеру порта. Выбирайте его в зависимости от того, какой компонент Minecraft будет подключаться.

## McHttp

`McHttp` предоставляет HTTP endpoint, который может вызывать аддон выделенного сервера Bedrock.

### Лучшие варианты использования

- Выделенный сервер Bedrock
- стабильные заскриптованные миры Bedrock
- среды, в которых игровой сервер может вызывать HTTP endpoint

### Сильные стороны

- самый простой производственный транспорт для BDS
- простая модель endpoint
- хорошо подходит для панелей, обратной схемы сети и выделенных хостов

### Компромиссы

- требуется доступность сети от сервера Bedrock до VoiceCraft
- может быть заблокирован у некоторых хостинг-провайдеров
- требуются разрешения сценария/модуля BDS, необходимые для аддона

### Типичная конфигурация

```json
{
  "McHttpConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "http://0.0.0.0:9050/"
  }
}
```

Используйте `http://127.0.0.1:9050/` только в том случае, если BDS и VoiceCraft работают на одном хосте.

## McWss

`McWss` предоставляет WebSocket endpoint и использует командный туннель в мире Bedrock.

### Лучшие варианты использования

- локальные миры Bedrock
- одиночное тестирование
- настройки с использованием `/connect` и туннелирования команд

### Сильные стороны

- работает без автономного рабочего процесса HTTP BDS
- практично для разработки и локальных демонстраций

### Компромиссы

- менее стабилен при большом давлении полезной нагрузки
- чувствителен к `CommandsPerTick` и ограничениям на фрагментирование полезной нагрузки
- обычно не лучший выбор для общедоступных производственных сред

### Типичная конфигурация

```json
{
  "McWssConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "ws://127.0.0.1:9051/",
    "DataTunnelCommand": "voicecraft:data_tunnel"
  }
}
```

Используйте это, когда вам нужен локальный поток `/connect`. Для настоящего производственного сервера BDS выберите `McHttp`.

## McTcp

`McTcp` предоставляет необработанный TCP-мост, используемый инфраструктурой на стороне Java.

### Лучшие варианты использования

- `GeyserVoice`
- Java-сервер или прокси-мосты
- прямая интеграция среды выполнения Paper

### Сильные стороны

- прямой мостовой транспорт для плагинов на стороне Java
- избегает семантики HTTP endpoint, когда собственный TCP-мост лучше
- соответствует текущей архитектуре `GeyserVoice`

### Компромиссы

- еще один порт для управления
- наиболее полезно, когда вы действительно запускаете мост на стороне Java
- не используется пакетами аддонов Bedrock

### Типичная конфигурация

```json
{
  "McTcpConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "0.0.0.0",
    "Port": 9050
  }
}
```

Если `GeyserVoice` работает на том же компьютере, что и VoiceCraft, привяжите его к `127.0.0.1`. Если он работает где-то еще, привяжите его к адресу, к которому плагин может получить доступ, и ограничьте брандмауэр.

## Какой из них выбрать?

### Выделенный сервер Bedrock

Используйте `McHttp`.

Продолжите с [McHttp for BDS](/minecraft/mchttp-bds).

### Bedrock одиночная игра / локальный мир

Используйте `McWss`.

Продолжите с [McWss for Singleplayer Worlds](/minecraft/mcwss-singleplayer).

### Java + Geyser/Floodgate

Используйте `McTcp` для `GeyserVoice`.

Продолжите с [GeyserVoice](/ecosystem/geyservoice).

### Смешанная сеть

Вы можете запустить более одного транспорта, но предоставлять только то, что вам действительно нужно.

Распространенные смешанные случаи:

- Bedrock BDS плюс мост Java:
  включить `McHttp` и `McTcp`
- локальное тестирование, пока производство остается на BDS:
  запустить отдельную папку тестового сервера вместо повторного использования производственных токенов
- прокси-сеть:
  обычно предоставляют владельцу прокси только `McTcp`

## Советы по безопасности

- заменить все токены входа
- привязать к `127.0.0.1`, когда подключающаяся сторона локальна
- привязывайтесь к `0.0.0.0` только тогда, когда требуется удаленный доступ
- соблюдать строгие правила брандмауэра для каждого транспорта
- не раскрывайте неактивные транспорты только потому, что они доступны

## Контрольный список проверки

- выбранное транспортное поле `Enabled` — `true`
- установлен соответствующий аддон/плагин
- хост и порт endpoint доступны из среды выполнения Minecraft
- токен аддона/плагина соответствует правильному `LoginToken`
- журналы сервера показывают подключение клиента транспорта
- процесс привязки работает после входа в систему транспорта
