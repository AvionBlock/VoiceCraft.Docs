# Режимы транспорта

VoiceCraft имеет несколько транспортных слоев, ориентированных на Minecraft. Выбор правильного варианта важен для обеспечения стабильности и простоты развертывания.

Транспорт — это путь, по которому автоматизация Minecraft отправляет состояние в `VoiceCraft.Server`. Он отделен от голосового UDP-эндпоинта, который используют клиенты игроков.

Используйте эту страницу перед редактированием `McHttpConfig`, `McWssConfig` или `McTcpConfig`.

## Быстрое сравнение

| Транспорт | Типичный клиент | Форма эндпоинта | Лучше всего подходит для | Поле токена |
|-----------|------------------|----------------|----------|-------------|
| `McHttp` | `VoiceCraft.Addon.Core.McHttp` | HTTP-эндпоинт | Выделенный сервер Bedrock | `McHttpConfig.LoginToken` |
| `McWss` | `VoiceCraft.Addon.Core.McWss` | WebSocket + командный туннель | локальные миры Bedrock и тестирование | `McWssConfig.LoginToken` |
| `McTcp` | `VoiceCraft.Java` | необработанный TCP-мост | сценарии Java, Geyser, прокси или Paper bridge | `McTcpConfig.LoginToken` |

Не выбирайте транспорт только по номеру порта. Выбирайте его в зависимости от того, какой компонент Minecraft будет подключаться.

## McHttp

`McHttp` предоставляет HTTP-эндпоинт, который может вызывать аддон выделенного сервера Bedrock.

### Лучшие варианты использования

- Выделенный сервер Bedrock
- стабильные скриптовые миры Bedrock
- среды, в которых игровой сервер может вызывать HTTP-эндпоинт

### Сильные стороны

- самый простой production-транспорт для BDS
- простая модель эндпоинта
- хорошо подходит для панелей, reverse proxy и выделенных хостов

### Компромиссы

- требуется доступность сети от сервера Bedrock до VoiceCraft
- может быть заблокирован у некоторых хостинг-провайдеров
- требуются разрешения скриптов/модулей BDS, необходимые для аддона

### Типичная конфигурация

```json
{
  "McHttpConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "http://0.0.0.0:9050/"
  }
}
```

Используйте `http://127.0.0.1:9050/` только в том случае, если BDS и VoiceCraft работают на одном хосте.

## McWss

`McWss` предоставляет WebSocket-эндпоинт и использует командный туннель в мире Bedrock.

### Лучшие варианты использования

- локальные миры Bedrock
- одиночное тестирование
- настройки с использованием `/connect` и туннелирования команд

### Сильные стороны

- работает без автономного рабочего процесса HTTP BDS
- практично для разработки и локальных демонстраций

### Компромиссы

- менее стабилен при высокой нагрузке полезной нагрузки
- чувствителен к `CommandsPerTick` и ограничениям на разбиение полезной нагрузки
- обычно не лучший выбор для публичных production-сред

### Типичная конфигурация

```json
{
  "McWssConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "ws://127.0.0.1:9051/",
    "DataTunnelCommand": "voicecraft:data_tunnel"
  }
}
```

Используйте это, когда вам нужен локальный сценарий `/connect`. Для реального production-сервера BDS выберите `McHttp`.

## McTcp

`McTcp` предоставляет необработанный TCP-мост, используемый инфраструктурой на стороне Java.

### Лучшие варианты использования

- `VoiceCraft.Java`
- Java-сервер или прокси-мосты
- прямая интеграция среды выполнения Paper

### Сильные стороны

- прямой транспорт-мост для плагинов на стороне Java
- избегает семантики HTTP-эндпоинта, когда нативный TCP-мост лучше
- соответствует текущей архитектуре `VoiceCraft.Java`

### Компромиссы

- еще один порт для управления
- наиболее полезен, когда вы действительно запускаете мост на стороне Java
- не используется пакетами аддонов Bedrock

### Типичная конфигурация

```json
{
  "McTcpConfig": {
    "Enabled": true,
    "LoginToken": "replace-with-token",
    "Hostname": "0.0.0.0",
    "Port": 9050
  }
}
```

Если `VoiceCraft.Java` работает на том же компьютере, что и VoiceCraft, привяжите его к `127.0.0.1`. Если он работает где-то еще, привяжите его к адресу, к которому плагин может получить доступ, и ограничьте брандмауэр.

## Какой из них выбрать?

### Выделенный сервер Bedrock

Используйте `McHttp`.

Продолжите с [McHttp for BDS](/minecraft/mchttp-bds).

### Bedrock одиночная игра / локальный мир

Используйте `McWss`.

Продолжите с [McWss for Singleplayer Worlds](/minecraft/mcwss-singleplayer).

### Java + Geyser/Floodgate

Используйте `McTcp` для `VoiceCraft.Java`.

Продолжите с [VoiceCraft.Java](/ecosystem/voicecraft-java).

### Смешанная сеть

Вы можете запустить более одного транспорта, но открывайте наружу только то, что вам действительно нужно.

Распространенные смешанные случаи:

- Bedrock BDS плюс мост Java:
  включить `McHttp` и `McTcp`
- локальное тестирование, пока производство остается на BDS:
  запустить отдельную папку тестового сервера вместо повторного использования производственных токенов
- прокси-сеть:
  обычно открывайте только `McTcp` для владельца прокси

## Советы по безопасности

- замените все токены входа
- привязать к `127.0.0.1`, когда подключающаяся сторона локальна
- привязывайтесь к `0.0.0.0` только тогда, когда требуется удаленный доступ
- соблюдать строгие правила брандмауэра для каждого транспорта
- не раскрывайте неактивные транспорты только потому, что они доступны

## Контрольный список проверки

- выбранное транспортное поле `Enabled` — `true`
- установлен соответствующий аддон/плагин
- хост и порт эндпоинта доступны из среды выполнения Minecraft
- токен аддона/плагина соответствует правильному `LoginToken`
- журналы сервера показывают подключение клиента транспорта
- процесс привязки работает после аутентификации транспорта
