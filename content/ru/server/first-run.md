# Первый запуск сервера

Эта страница открывается после того, как вы уже один раз загрузили и запустили `VoiceCraft.Server`. Цель состоит в том, чтобы превратить этот первый запуск в рабочий сервер, который смогут использовать клиенты и Minecraft.

## Что происходит при первом запуске

При запуске VoiceCraft ищет `ServerProperties.json` в текущем каталоге и подкаталогах.

Если файл не найден, сервер автоматически создает:

- `config/`
- `config/ServerProperties.json`

Этот файл становится основным постоянным источником достоверной информации о поведении сервера.

После появления файла остановите сервер, отредактируйте конфиг, затем запустите его снова. Первый запуск создает только базовый уровень; настройка еще не завершена.

## Порты и эндпоинты по умолчанию

По умолчанию сгенерированная конфигурация выровнена следующим образом:

- VoiceCraft UDP: `9050`
- `McHttp`: `http://127.0.0.1:9050/`
- `McWss`: `ws://127.0.0.1:9051/`
- `McTcp`: `127.0.0.1:9050`

Примечания:

- Голосовой трафик UDP и некоторые настройки транспорта по умолчанию используют общий `9050`
- `McWss` по умолчанию отделяется от `9051`.
- `McTcp` особенно актуален для `VoiceCraft.Java`.

## Линейный путь первого запуска

### 1. Остановите сервер и откройте сгенерированный конфиг

Открыто:

```text
config/ServerProperties.json
```

Сохраните этот файл в той же папке установки и включите его в резервные копии.

### 2. Замените сгенерированные токены

Прежде чем подключиться к любому аддону, плагину или клиенту игрока, замените:

- `McHttpConfig.LoginToken`
- `McWssConfig.LoginToken`
- `McTcpConfig.LoginToken`

Используйте токен от транспорта, который вы фактически подключите позже. Например, команда BDS `vcconnect` должна использовать `McHttpConfig.LoginToken`, а VoiceCraft.Java — `McTcpConfig.LoginToken`.

### 3. Выберите один основной транспорт Minecraft

Используйте топологию, чтобы решить, что следует включить:

| Настройка | Включить | Продолжить с |
|-------|--------|---------------|
| Выделенный сервер Bedrock | `McHttpConfig` | [McHttp for BDS](/minecraft/mchttp-bds) |
| Локальный мир Bedrock | `McWssConfig` | [McWss for Singleplayer Worlds](/minecraft/mcwss-singleplayer) |
| Java + Geyser/Floodgate | `McTcpConfig` | [VoiceCraft.Java](/ecosystem/voicecraft-java) |

Вы можете запустить несколько транспортов, но первую настройку легче отладить, если доступен только необходимый.

### 4. Установите привязки хоста

Используйте локальные привязки, когда все работает на одной машине:

- `McHttpConfig.Hostname = http://127.0.0.1:9050/`
- `McWssConfig.Hostname = ws://127.0.0.1:9051/`
- `McTcpConfig.Hostname = 127.0.0.1`

Используйте `0.0.0.0` только в том случае, если другой компьютер, контейнер или игровой хост должен подключиться к VoiceCraft.

### 5. Перезагрузите сервер

Запустите `VoiceCraft.Server` еще раз из той же папки. Следите за:

- недопустимые ошибки JSON
- ошибки «порт уже используется»
- ошибки запуска слушателя или привязки

Исправьте это, прежде чем двигаться дальше. Аддон или плагин Minecraft не может надежно подключиться, пока сервер сообщает об ошибках запуска.

### 6. Подключите клиент VoiceCraft

Установите клиент со [страницы загрузки](/download), затем добавьте запись сервера:

- хост: адрес сервера VoiceCraft
- порт: `VoiceCraftConfig.Port`, обычно `9050`

Для локального тестирования используйте:

```text
127.0.0.1:9050
```

Убедитесь, что клиент `Positioning Type` соответствует `VoiceCraftConfig.PositioningType`.

### 7. Подключите Minecraft

Продолжите следовать руководству, соответствующему включенному вами транспорту:

- [McHttp for BDS](/minecraft/mchttp-bds)
- [McWss for Singleplayer Worlds](/minecraft/mcwss-singleplayer)
- [VoiceCraft.Java](/ecosystem/voicecraft-java)

При запросе токена используйте соответствующий транспортный токен из `ServerProperties.json`.

### 8. Проверьте настройку

Первая настройка завершена, когда:

- журналы сервера не показывают ошибок конфигурации или прослушивателя
- клиент VoiceCraft подключается к UDP-эндпоинту
- Minecraft аутентифицируется через выбранный транспорт
- процесс привязки в игре работает
- обновления позиций игроков достигают VoiceCraft
- звук с учетом расстояния работает на ожидаемой дистанции

## Аргументы запуска

Сервер VoiceCraft поддерживает следующие корневые аргументы:

- `--exit-on-invalid-properties`
  Выйдите, если `ServerProperties.json` невозможно проанализировать.
- `--language <culture>`
  Переопределить язык журнала сервера для текущего запуска.
- `--transport-mode <mode>`
  Включите подмножество транспорта Minecraft для текущего запуска.
- `--transport-host <host>`
  Переопределить настроенный транспортный узел Minecraft.
- `--transport-port <port>`
  Переопределить настроенный транспортный порт Minecraft.
- `--server-key <token>`
  Переопределить общий токен входа на стороне Minecraft для текущего запуска.

В коде также существуют короткие псевдонимы:

- `-eip`
- `-l`
- `-tm`
- `-th`
- `-tp`
- `-sk`

## Примеры

### Запуск с переопределением языка запуска

```bash
./VoiceCraft.Server --language en-US
```

### Выйти, если конфигурация недействительна

```bash
./VoiceCraft.Server --exit-on-invalid-properties
```

### Запускайте только `McTcp` для моста Java.

```bash
./VoiceCraft.Server --transport-mode tcp --transport-host 0.0.0.0 --transport-port 9050
```

### Запускать только `McHttp`

```bash
./VoiceCraft.Server --transport-mode http --transport-host 0.0.0.0 --transport-port 9050
```

### Переопределить токен без редактирования JSON

```bash
./VoiceCraft.Server --server-key "replace-with-secure-token"
```

## Как ведут себя переопределения транспорта

Переопределения во время выполнения не перезаписывают `ServerProperties.json` навсегда.

Они применяются только к текущему процессу и полезны, когда:

- запуск нескольких сред из одного образа
- использование панелей или systemd drop-ins
- тестирование топологий прямого и прокси-сервера
- разрешить другому инструменту, например `VoiceCraft.Java`, запускать среду выполнения с сгенерированными значениями

## Контрольный список при первом запуске

1. Запустите сервер один раз, чтобы сгенерировать `config/ServerProperties.json`.
2. Остановите сервер перед редактированием сгенерированной конфигурации.
3. Измените все сгенерированные токены входа.
4. Подтвердите, какой транспорт вам действительно нужен:
   - `McHttp` для BDS
   - `McWss` для локальных миров
   - `McTcp` для `VoiceCraft.Java`
5. Проверьте привязки хоста.
6. Открывайте только те порты, которые вам нужны.
7. Перезагрузите сервер из той же папки установки.
8. Подтвердите `PositioningType` своим клиентам.
9. Проверьте подключение клиента перед подключением автоматизации Minecraft.
10. Подключите аддон или плагин Minecraft и проверьте процесс привязки.

## Распространенные ошибки при первом запуске

- оставляя сгенерированные токены без изменений
- предоставление доступа к эндпоинтам `127.0.0.1` удаленным узлам
- забывая, что `McTcp` может потребоваться мостам на стороне Java
- позволяя использовать каждый транспорт в производстве, фактически не нуждаясь в нем
- редактирование `ServerProperties.json`, когда менеджер процессов немедленно перезапускает старую нерабочую конфигурацию
- использование UDP-порта клиента там, где руководство Minecraft ожидает эндпоинт транспорта

Полную информацию о конфигурации см. в разделе [ServerProperties.json](/server/server-properties).
