# Руководство по прокси GeyserVoice

Используйте этот режим при запуске Velocity или BungeeCord с одним или несколькими внутренними серверами Paper.

В режиме прокси поддерживается одно центральное соединение VoiceCraft через прокси, в то время как внутренние серверы Paper передают в потоковом режиме снимки игрока через обмен сообщениями плагина.

Форма цели:

```text
Backend Paper + GeyserVoice -> proxy relay -> Velocity/Bungee + GeyserVoice -> McTcp -> VoiceCraft.Server
VoiceCraft.Client -> VoiceCraft UDP endpoint
```

## Как работает режим прокси

- Backend-серверы Paper отправляют снимки игроков на прокси
- прокси-серверу принадлежит соединение `McTcp` на стороне VoiceCraft
- Идентификаторы мира и измерения могут быть размещены в пространстве имен с внутренней идентификацией.

Это позволяет использовать один центральный голосовой мост для сети с несколькими серверами.

## Шаблон развертывания

Установите GeyserVoice:

- на прокси
- на каждом внутреннем сервере Paper

## Основное правило

Прокси является источником достоверных данных для соединения VoiceCraft.

Внутренние серверы Paper следует рассматривать как производителей моментальных снимков, а не как основного владельца моста.

## Конфигурация backend Paper

На внутренних серверах Paper:

- включить режим прокси для узла Paper-side
- не рассматривайте серверный хост/порт/ключ как источник истины

Пример Paper backend:

```yml
config:
  proxy:
    enabled: true
```

Бэкэнду по-прежнему требуется установленный GeyserVoice, чтобы он мог наблюдать за игроками и отправлять снимки, но он не должен владеть основным соединением VoiceCraft.

## Конфигурация прокси

На прокси:

- установите настоящий `config.voicecraft.transport.host`
- установите настоящий `config.voicecraft.transport.port`
- установите настоящий `config.voicecraft.transport.login-token`

Пример скорости/банджи:

```yml
config:
  voicecraft:
    transport:
      host: "127.0.0.1"
      port: 9050
      login-token: "replace-with-token"
    voice:
      port: 1111
```

Токен должен соответствовать `McTcpConfig.LoginToken` на `VoiceCraft.Server`.

## Порядок настройки

1. Установите плагин на прокси и серверные узлы.
2. Запустите все один раз, чтобы сгенерировать конфиги.
3. Настройте прокси-сервер с реальным соединением VoiceCraft.
4. Настройте внутренние узлы для работы с прокси-ретрансляцией.
5. Перезагрузите плагин.
6. Подтвердить межсерверное перемещение и проверить процесс привязки.

Сначала начните с одного внутреннего сервера. После того, как обновления привязки и положения заработают, добавьте больше серверных узлов.

## Контрольный список проверки

- игрок присоединяется к бэкэнду
- серверная часть правильно отправляет снимки
- прокси остается подключенным к VoiceCraft
- переключение внутренних серверов сохраняет ожидаемую голосовую идентичность
- Журналы сервера VoiceCraft показывают одного клиента `McTcp`, принадлежащего прокси-серверу.
- Идентификаторы/размеры серверного мира остаются стабильными после переключения серверов

## Шаблоны отказов

- бэкэнд пытается завладеть основным соединением
- прокси-токен отличается от VoiceCraft `McTcpConfig.LoginToken`
- прокси-сервер может достигать Paper, но не VoiceCraft
- топология серверной части скрывает или перезаписывает сообщения плагина
- Плагин установлен на прокси, но отсутствует в одном бэкэнде
- серверная часть `config.proxy.enabled` имеет значение false в развертывании прокси-ретрансляции

## Операционные примечания

- По возможности держите VoiceCraft ближе к прокси-серверу, чтобы уменьшить задержку моста.
- Перезапустите или перезагрузите серверные узлы после изменения конфигурации прокси-реле.
- Сохраняйте токены в конфигурации прокси, а не дублируйте их случайным образом на каждом бэкэнде.
- Проверьте процесс привязки еще раз после добавления нового внутреннего сервера.
