# Производственные схемы

На этой странице собраны разумные подходы к production-развертыванию, а не сырой список функций.

Используйте эти схемы, когда решаете, какую топологию стандартизировать. Они намеренно предлагают конкретное мнение: цель — уменьшить количество движущихся частей, а не включать все возможные транспорты сразу.

## Схема 1: сервер только для Bedrock

Использование:

- `VoiceCraft.Server`
- `McHttp`
- `VoiceCraft.Addon.Core.McHttp`

Почему:

- самое чистое и стабильное развертывание Bedrock
- проще всего контролировать
- проще всего объяснить персоналу сервера

Рекомендуемая форма:

```text
BDS addon -> McHttp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Оставьте `McWss` и `McTcp` отключенными, если у вас нет особой причины для их запуска.

## Схема 2: локальное сообщество/SMP с Geyser

Использование:

- `VoiceCraft.Server`
- `McTcp`
- `VoiceCraft.Java` режим Direct Paper

Необязательно:

- позвольте VoiceCraft.Java управлять средой выполнения VoiceCraft, если вы предпочитаете единый процесс установки на стороне Java

Рекомендуемая форма:

```text
Paper/Folia + VoiceCraft.Java -> McTcp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Это хорошо подходит, когда один сервер на стороне Java является основным источником информации о позиции игрока.

## Схема 3: Большая сеть Java

Использование:

- внешний `VoiceCraft.Server`
- `McTcp`
- `VoiceCraft.Java` на прокси
- `VoiceCraft.Java` на внутренних узлах

Почему:

- центральное управление
- более чистое масштабирование
- более простой перезапуск, не затрагивая каждый бэкэнд

Рекомендуемая форма:

```text
backend Paper nodes -> proxy relay -> proxy VoiceCraft.Java -> McTcp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Оставьте прокси единственным владельцем соединения VoiceCraft. Внутренние узлы должны создавать снимки, а не конкурировать за основное соединение `McTcp`.

## Схема 4: Среда сборки/тестирования

Использование:

- `McWss`
- `Core.McWss`
- локальный экземпляр VoiceCraft

Почему:

- быстрый локальный цикл
- хорошо подходит для тестирования автоматизации аддонов

Рекомендуемая форма:

```text
local Bedrock world -> McWss -> local VoiceCraft.Server
local client -> local VoiceCraft UDP endpoint
```

Не рассматривайте это как производственный дизайн по умолчанию для общедоступного сервера Bedrock. Перейдите к `McHttp`, когда мир станет долгоиграющим или общим.

## Выбор чертежа

| Нужна | Выберите |
|------|--------|
| Стабильный production для Bedrock | Схема 1 |
| Один сервер Java/Geyser | Схема 2 |
| Сеть Velocity/Bungee | Схема 3 |
| Локальное тестирование или разработка аддонов | Схема 4 |

## Оперативные рекомендации

- по возможности храните логи VoiceCraft отдельно от игровых логов
- ротируйте или архивируйте конфигурации перед крупными обновлениями
- держите транспортные токены в секрете
- тестируйте процесс привязки после каждого изменения топологии
- открывайте наружу только тот транспорт, который требуется выбранной схеме
- сохраните копию `ServerProperties.json` перед изменением портов или токенов
- задокументируйте, какой сервис владеет процессом VoiceCraft в вашей среде.
