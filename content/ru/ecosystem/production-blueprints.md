# Производственные чертежи

На этой странице представлены разумные подходы к производству, а не необработанные списки функций.

Используйте эти схемы, когда решаете, какую топологию следует стандартизировать. Они намеренно самоуверенны: цель состоит в том, чтобы уменьшить количество движущихся частей, а не разоблачить все возможные транспортные средства сразу.

## Схема 1: сервер только для Bedrock

Использование:

- `VoiceCraft.Server`
- `McHttp`
- `VoiceCraft.Addon.Core.McHttp`

Почему:

- самое чистое и стабильное развертывание Bedrock
- проще всего контролировать
- проще всего объяснить персоналу сервера

Рекомендуемая форма:

```text
BDS addon -> McHttp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Оставьте `McWss` и `McTcp` отключенными, если у вас нет особой причины для их запуска.

## Схема 2: Местное сообщество/SMP с Гейзером

Использование:

- `VoiceCraft.Server`
- `McTcp`
- `GeyserVoice` режим Direct Paper

Необязательно:

- позвольте GeyserVoice управлять средой выполнения VoiceCraft, если вы предпочитаете единый процесс установки на стороне Java

Рекомендуемая форма:

```text
Paper/Folia + GeyserVoice -> McTcp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Это хорошо подходит, когда один сервер на стороне Java является основным источником информации о позиции игрока.

## Схема 3: Большая сеть Java

Использование:

- внешний `VoiceCraft.Server`
- `McTcp`
- `GeyserVoice` на прокси
- `GeyserVoice` на внутренних узлах

Почему:

- центральное управление
- более чистое масштабирование
- более простой перезапуск, не затрагивая каждый бэкэнд

Рекомендуемая форма:

```text
backend Paper nodes -> proxy relay -> proxy GeyserVoice -> McTcp -> VoiceCraft.Server
players -> VoiceCraft UDP endpoint
```

Оставьте прокси единственным владельцем соединения VoiceCraft. Внутренние узлы должны создавать снимки, а не конкурировать за основное соединение `McTcp`.

## Схема 4: Среда сборки/тестирования

Использование:

- `McWss`
- `Core.McWss`
- локальный экземпляр VoiceCraft

Почему:

- быстрая местная линия
- хорошо подходит для тестирования автоматизации дополнений

Рекомендуемая форма:

```text
local Bedrock world -> McWss -> local VoiceCraft.Server
local client -> local VoiceCraft UDP endpoint
```

Не рассматривайте это как производственный дизайн по умолчанию для общедоступного сервера Bedrock. Перейдите к `McHttp`, когда мир станет долгоиграющим или общим.

## Выбор чертежа

| Нужна | Выберите |
|------|--------|
| Стабильная добыча коренных пород | Чертеж 1 |
| Один сервер Java/Geyser | Чертеж 2 |
| Сеть скорости/банджи | Чертеж 3 |
| Локальное тестирование или разработка дополнений | Чертеж 4 |

## Оперативные рекомендации

- по возможности храните логи VoiceCraft отдельно от игровых логов
- ротация или архивирование конфигураций перед крупными обновлениями
- держите транспортные жетоны в секрете
- тестируйте поток привязки после каждого изменения топологии
- выставлять только тот транспорт, который требуется выбранным планом
- сохраните копию `ServerProperties.json` перед изменением портов или токенов
- документ, какой сервис владеет процессом VoiceCraft в вашей среде.
