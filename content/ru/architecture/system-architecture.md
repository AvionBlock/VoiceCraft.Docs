# Архитектура системы

VoiceCraft — это стек голосового чата с учетом расстояния, а не отдельный мод Minecraft. Клиент передает звук с микрофона, сервер управляет голосовыми сеансами и общим состоянием, а слой интеграции Minecraft сообщает серверу, где находятся игроки и как они должны быть представлены.

Разделение является намеренным: один и тот же голосовой сервер может работать с выделенным сервером Bedrock, локальными мирами Bedrock, прямыми серверами Paper и прокси-сетями, если подключен правильный транспорт, ориентированный на Minecraft.

## Основные слои

| Слой | Основная ответственность | Типичное место установки |
|-------|---------------------|--------------------------|
| `VoiceCraft.Client` | Захватывает вход микрофона, отправляет голосовые пакеты, воспроизводит голоса ближайших игроков и хранит локальные настройки звука. | Устройство игрока |
| `VoiceCraft.Server` | Принимает голосовые клиенты, хранит состояние сущностей, применяет флаги модерации и настройки аудиоэффектов по умолчанию, предоставляет транспорты Minecraft. | VPS, игровой хост, локальный ПК или среда выполнения, управляемая плагином |
| Интеграция Minecraft | Отправляет в VoiceCraft данные о положении игрока/сущности и события жизненного цикла из Minecraft. | Аддон Bedrock, плагин Paper или прокси-плагин |

### Клиентский уровень

`VoiceCraft.Client` обрабатывает:

- захват микрофона и предварительная обработка
- режим «нажми и говори», отключение звука, оглушение, выбор устройства ввода/вывода
- UDP-соединение с `VoiceCraft.Server`
- воспроизведение звука с учетом расстояния на основе состояния сервера
- локальная громкость для каждого пользователя и локальные настройки отключения звука

В обычной серверной модели клиент сам не определяет позиции игроков Minecraft. Сущности и состояние мира приходят от сервера и интеграции Minecraft.

### Серверный уровень

`VoiceCraft.Server` обрабатывает:

- UDP-сеансы клиентов VoiceCraft
- состояние сетевой сущности и состояние привязки
- флаги модерации на стороне сервера
- битовые маски эффектов и настройки аудиоэффектов по умолчанию
- Транспорты для Minecraft: `McHttp`, `McWss` и `McTcp`.
- постоянная конфигурация в `config/ServerProperties.json`

Сервер — это общая среда выполнения, с которой должны согласовываться как клиенты игроков, так и интеграция со стороны Minecraft. Если клиент подключается, а Minecraft нет, игроки могут отображаться в виде голосовых сеансов без полезных данных о мировом положении.

### Слой интеграции Minecraft

Это зависит от топологии:

- `VoiceCraft.Addon.Core.McHttp` для выделенного сервера Bedrock
- `VoiceCraft.Addon.Core.McWss` для локальных миров Bedrock и настроек командного туннеля
- `VoiceCraft.Java` для топологий Java, Geyser/Floodgate, Paper, Velocity и BungeeCord

Уровень интеграции отвечает за перевод игровых событий в состояние VoiceCraft: присоединение игрока, уход игрока, обновление позиций, идентификаторы миров, запросы привязки, фейковые сущности, изменения эффектов и жизненный цикл соединения.

## Основные понятия данных

VoiceCraft вращается вокруг сущностей, а не только необработанных сокетов.

Сущности несут в себе такие состояния, как:

- имя
- титул
- описание
- позиция
- вращение
- идентификатор мира
- состояние mute/deafen
- битовые маски эффектов

Сетевые клиенты могут быть представлены как сущности, а интеграция Minecraft также может создавать или обновлять сущности. Эта модель позволяет VoiceCraft описывать реальных игроков, фейковые или отображаемые сущности и кастомные голосовые цели, управляемые миром, с помощью одного и того же конвейера состояний.

## Почему транспорты разделены

Голосовой трафик VoiceCraft и автоматизация Minecraft не всегда живут в одной и той же среде.

Вот почему:

- клиент игрока общается с основным голосовым сервером UDP
- интеграция Bedrock или Java общается через транспорт Minecraft
- каждый транспорт может иметь свой собственный токен, привязку хоста и максимальный лимит клиентов.

Такое разделение позволяет поддерживать стабильность голосового сервера при изменении интеграции Minecraft. Например, при развертывании только Bedrock можно использовать `McHttp`, а в сети Java/Geyser можно сохранить тот же основной голосовой сервер, но переключить сторону Minecraft на `McTcp`.

## Типичные формы соединений

### Выделенный сервер Bedrock

```text
VoiceCraft.Client -> VoiceCraft UDP server
BDS + VoiceCraft.Addon.Core.McHttp -> McHttp endpoint
```

Используйте это, когда сервер Bedrock может достичь HTTP-эндпоинта, который предоставляет `VoiceCraft.Server`.

### Локальный мир Bedrock

```text
VoiceCraft.Client -> VoiceCraft UDP server
Minecraft local world + Core.McWss -> McWss websocket endpoint
```

Используйте это для локального тестирования или одиночных миров, где допустим командный туннель.

### Java + Geyser/Floodgate

```text
VoiceCraft.Client -> VoiceCraft UDP server
VoiceCraft.Java -> McTcp endpoint
```

Используйте это, когда инфраструктура на стороне Java является источником информации о позиции игрока и состоянии жизненного цикла.

## Что настроить в первую очередь

1. Настройте `VoiceCraft.Server` и убедитесь, что он запускается без проблем.
2. Выберите транспорт Minecraft, соответствующий топологии.
3. Убедитесь, что клиент подключается к `VoiceCraftConfig.Port`.
4. Убедитесь, что интеграция Minecraft проходит проверку подлинности с помощью соответствующего транспортного токена.
5. Проверьте процесс привязки и обновления позиций, прежде чем добавлять кастомное поведение.
